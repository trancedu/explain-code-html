Purpose and mental model

This file turns messy expense rows into a compact spending report. It is a self-contained, in-memory batch pipeline: callers supply a list of dictionaries with string date, merchant and amount fields, and process returns accepted and duplicate counts, rejected row numbers and reasons, category totals in integer cents, and a grand total. Running the file directly prints that report as JSON; importing it defines the records, rules, functions and sample without printing.

The strategy is to normalize before comparing. A date becomes an ISO date string, merchant whitespace collapses, and decimal money rounds to cents. Categorization uses the first matching keyword rule. A normalized date, case-folded merchant and cent amount identify a duplicate. Invalid rows are recorded and skipped; duplicate rows are counted and skipped; only distinct normalized expenses enter the category sums. This keeps the report tied to the same values used for comparison.

For example, {"date":"2026-10-16","merchant":" Costco ","amount":"$25.105"} becomes Expense("2026-10-16", "Costco", 2511, "groceries"). A later COSTCO row for 25.11 on that day adds one duplicate and no spending. The supplied six rows produce four accepted expenses and a grand total of 5101 cents. There is no currency field, exchange-rate conversion, file storage or network access.

The stages below connect module setup, normalization helpers, batch decisions and the executable example. Type annotations describe expected shapes; they do not enforce them for arbitrary callers.

Cleaning amounts and handling parse errors

parse_cents declares a string input and integer output. strip removes surrounding whitespace; replace removes every dollar sign and comma without checking their position. Amount constraints, rounding and cents

is_finite excludes NaN and infinity. The short-circuiting or prevents those values from reaching the <= 0 comparison; zero and negative amounts are rejected too. quantize fixes the exponent to 0.01. ROUND_HALF_UP rounds positive halfway values upward, so 25.105 becomes 25.11. Positivity is checked before rounding, followed by a separate zero check: 0.004 is rejected, whereas 0.005 becomes one cent. The function multiplies by 100 and converts to int. 04 / Limitations and possible changes

Implementation facts: Deduplication lasts for one call. Two real transactions with the same date, merchant and amount can be merged. Classification is ordered substring matching. Currency cleanup does not validate symbol placement. Amount arithmetic depends on the current Decimal context; very high precision amounts can interrupt the batch. Input types are constrained by exceptions encountered during operations.

Inferred intent: Integer cents and frozen records may reduce accumulation and accidental mutation risks. The code does not document its design motivation, and these choices do not establish complete accounting correctness.

Suggestions; source unchanged: Real accounting use could require transaction-ID deduplication, currency and amount-format validation, amount bounds and explicit handling of quantization errors. Business semantics should determine those changes.

05 / Self-check and further questions

Why is the second row not another groceries expense?

Both rows have the same date, case-fold to costco and round to 2511 cents. Their deduplication keys are equal. See block 10. Read the implementation.

Why is positive 0.004 still rejected?

The positivity check precedes rounding. Rounding produces 0.00, which triggers the separate rounded == 0 check. See block 5. Read the implementation.

Does "Uber Cafe" belong to dining?

The transport rule matches uber before dining is reached. categorize immediately returns transport. See block 6. Read the implementation.

Does process catch every amount error?

No. Decimal construction errors are converted to ValueError, but quantize is outside that try. Its InvalidOperation is absent from the process catch list. See blocks 4, 5 and 9. Read the implementation.

Modification: How would you accept refunds without accepting zero?

Change the pre-rounding condition to reject nonfinite values or values equal to zero, then keep the post-rounding zero check. Negative amounts would then affect category totals and deduplication. Review whether that behavior fits the caller before changing the source; the current implementation intentionally rejects all nonpositive amounts. Inspect the amount checks and the signed cent key.

Supplement: How do counts and complexity relate?

For input that finishes normally, every row is accepted, duplicated or rejected, so these three counts sum to the input row count. Assuming average set-lookup cost and a fixed keyword collection, processing grows with row count and total input text length. seen, expenses and rejected require memory that grows with row count. """Normalize, deduplicate, categorize and summarize sample USD expenses."""
from dataclasses import dataclass
from datetime import date
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP
import json


@dataclass(frozen=True)
class Expense:
    day: str
    merchant: str
    cents: int
    category: str


RULES = (
    ("groceries", ("costco", "trader joe", "whole foods")),
    ("transport", ("nj transit", "uber", "parking")),
    ("dining", ("cafe", "restaurant")),
)


def parse_cents(value: str) -> int:
    cleaned = value.strip().replace("$", "").replace(",", "")
    try:
        amount = Decimal(cleaned)
    except InvalidOperation as exc:
        raise ValueError("invalid amount") from exc
    if not amount.is_finite() or amount <= 0:
        raise ValueError("amount must be finite and positive")
    rounded = amount.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
    if rounded == 0:
        raise ValueError("amount rounds to zero")
    return int(rounded * 100)


def categorize(merchant: str) -> str:
    lowered = merchant.casefold()
    for category, keywords in RULES:
        if any(word in lowered for word in keywords):
            return category
    return "other"


def normalize(row: dict) -> Expense:
    day = date.fromisoformat(row["date"]).isoformat()
    merchant = " ".join(row["merchant"].split())
    if not merchant:
        raise ValueError("merchant is empty")
    return Expense(
        day=day,
        merchant=merchant,
        cents=parse_cents(row["amount"]),
        category=categorize(merchant),
    )


def process(rows: list[dict]) -> dict:
    seen = set()
    expenses = []
    rejected = []
    duplicates = 0
    for index, row in enumerate(rows, start=1):
        try:
            expense = normalize(row)
        except (KeyError, ValueError, TypeError, AttributeError) as exc:
            rejected.append({"row": index, "reason": str(exc)})
            continue
        key = (expense.day, expense.merchant.casefold(), expense.cents)
        if key in seen:
            duplicates += 1
            continue
        seen.add(key)
        expenses.append(expense)
    totals = {}
    for expense in expenses:
        previous = totals.get(expense.category, 0)
        totals[expense.category] = previous + expense.cents
    return {
        "accepted": len(expenses),
        "duplicates": duplicates,
        "rejected": rejected,
        "totals_cents": dict(sorted(totals.items())),
        "grand_total_cents": sum(totals.values()),
    }
